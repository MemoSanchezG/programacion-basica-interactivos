Consumir APIs con IA sin que piense por ti

  • Una IA escribe en segundos el código para consultar una API, pero no sabe qué responde HOY esa API: puede inventar parámetros, claves o direcciones que no existen.

import json
import requests

URL = "https://api.open-meteo.com/v1/forecast"
PARAMS = {"latitude": 25.67, "longitude": -100.31,
          "timezone": "America/Monterrey",
          "daily": "temperature_2m_max,temperature_2m_min"}

def obtener(url, params):
    r = requests.get(url, params=params, timeout=10)
    r.raise_for_status()
    return r.json()

def normalizar(d):
    filas = zip(d["time"], d["temperature_2m_max"],
                d["temperature_2m_min"])
    return [{"fecha": f, "tmax": a, "tmin": b} for f, a, b in filas]

registros = normalizar(obtener(URL, PARAMS)["daily"])
validos = [r for r in registros if None not in r.values()]
with open("pronostico.json", "w", encoding="utf-8") as f:
    json.dump(validos, f, indent=2)
print(len(validos), "días guardados:", validos[0])

Reto integrador: módulo de consumo de datos20 min

  1. obtener(): pide al archivo histórico de Open-Meteo las máximas, mínimas y lluvia diarias de Monterrey de septiembre de 2026, con timeout y raise_for_status dentro de try/except.
  2. normalizar() → lista de registros {fecha, tmax, tmin, lluvia_mm}; validar() → solo números (no bool) y tmin ≤ tmax; registra los inválidos con su motivo.
  3. Guarda los válidos en clima_septiembre.json e imprime cuántos días se guardaron, el día más caluroso y la lluvia total del mes.

Pista: Usa los PARAMS del código de partida tal cual: la API los pide con esos nombres. La lluvia viene en precipitation_sum. sum() y max() funcionan sobre listas por comprensión.
