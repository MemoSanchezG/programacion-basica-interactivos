    En Linux y macOS: el shebang y los permisos

    En Linux y macOS también puedes escribir python3 hola.py. Pero un script se puede ejecutar como cualquier programa si cumple dos cosas: su primera línea dice con qué intérprete se corre (el shebang) y tiene permiso de ejecución.

    1. La primera línea: el shebang

    1. #!/usr/bin/env python3
    2. # hola.py: mi primer programa
    3. nombre = "Ana"
    4. print("Hola,", nombre)
    5. print("Bienvenida a Programación Básica")

    #! se lee "shebang". Le dice al sistema qué programa debe leer el archivo. /usr/bin/env python3 busca python3 en el PATH, igual que cuando lo escribes en la terminal; por eso respeta el entorno virtual activo. Para Python esa línea es solo un comentario.

    2. Correrlo en la terminal

    a) Como siempre, pidiéndole a Python que lo lea:
    alumno@laptop:~/programacion$ python3 hola.py Hola, Ana Bienvenida a Programación Básica
    b) Como programa: ./ quiere decir "en esta carpeta" (en Linux la carpeta actual no está en el PATH). Sin permiso de ejecución, el sistema no lo deja correr:
    alumno@laptop:~/programacion$ ./hola.py bash: ./hola.py: Permission denied
    c) chmod +x le da permiso de ejecución (solo una vez). Ahora sí:
    alumno@laptop:~/programacion$ chmod +x hola.py alumno@laptop:~/programacion$ ./hola.py Hola, Ana Bienvenida a Programación Básica
    ¿Y en Windows? cmd no usa el shebang ni los permisos: el sistema decide con qué programa abrir un archivo por su extensión (.py). Por eso en Windows se escribe python hola.py. Aun así, conviene dejar el shebang en tus scripts: no estorba y el mismo archivo funciona en Linux y macOS.
