Cómo usar la IA esta semana

Depurar con IA sin perder el aprendizaje

  • Esta semana verás muchos errores a propósito. La IA puede ayudarte a entenderlos, con una regla del temario (Fase 2): no le pidas que corrija un error que tú no has intentado depurar.
  • Primero tú: lee el traceback (tipo, mensaje y línea) y escribe tu hipótesis: "creo que falla porque...".
  • Después la IA: pégale el traceback y tu hipótesis, y pídele preguntas guía o una pista, no el código corregido.
  • Hábito profesional: antes de pegar un error en una IA, revisa que no incluya contraseñas, datos personales ni información privada.

Día 1

Excepciones: cuando el programa truena

Qué es una excepción, los tipos más comunes y cómo leer un traceback

Ejemplos de la clase (ábrelos en PythonTutor)

  • ValueError: int('veinte')
  • TypeError: '5' + 3
  • ZeroDivisionError: 10 / 0
  • IndexError: [10, 20, 30][3]
  • KeyError: {'a': 1}['b']
  • NameError: pritn('hola')
  • AttributeError: [1, 2].add(3)
  • Anatomía de un traceback

Reto: caza de errores con el traceback 20 min

  1. Abre el código de partida (enlace en la pista): es un reporte de calificaciones con 3 errores que aparecen uno por uno.
  2. Córrelo. Antes de corregir cada excepción, anota en tu libreta: tipo, mensaje, línea y tu hipótesis de la causa.
  3. Corrige el código o los datos (hoy sin try/except) y vuelve a correr hasta que imprima las 3 líneas del reporte.

Pista: Lee primero la ÚLTIMA línea del traceback. Pregúntate: ¿están mal los datos o está mal el código?

Código de partida

# Reporte de calificaciones: tiene 3 errores
califs = {'Ana': 95, 'Luis': '80', 'Eva': 72}

def promedio(datos):
    total = 0
    for nombre in datos:
        total = total + datos[nombre]
    return total / len(datos)

print('Promedio:', promedio(califs))
print('Beto:', califs['Beto'])
valores = list(califs.values())
print('Última:', valores[len(valores)])

Atrapar la excepción correcta, leer su mensaje y seguir adelante

Ejemplos de la clase (ábrelos en PythonTutor)

  • Un mensaje distinto para cada error

Reto: una calculadora que no truena 20 min

  1. Escribe pedir_numero(mensaje): repite input() dentro de un while True y regresa el número (float) solo cuando el texto sea válido.
  2. Si float() lanza ValueError, muestra qué escribió la persona y qué se esperaba, y vuelve a pedir el dato.
  3. Con pedir_numero lee a y b e imprime a / b; si b es 0, atrapa ZeroDivisionError con su propio mensaje. Prueba con: diez, 10, 0.

Pista: Un return dentro del try sale de la función (y del while) solo si float() funcionó; si falla, el except avisa y el ciclo repite.

Código de partida

def pedir_numero(mensaje):
    texto = input(mensaje)
    return float(texto)

a = pedir_numero('a = ')

Día 4

Limpieza y cierre de recursos

Limpieza de recursos: else, finally y with

Ejemplos de la clase (ábrelos en PythonTutor)

  • finally se ejecuta incluso después de return
  • Un close() que nunca llega vs. with (así no: close() dentro del try)
  • Un close() que nunca llega vs. with (así sí: with cierra al salir)

Reto: garantiza el cierre de una conexión 20 min

  1. Abre el código de partida: con el dato -3 el programa truena y la conexión nunca se cierra (mira el atributo abierta en PythonTutor).
  2. Usa try/finally para que conexion.cerrar() se ejecute siempre, aunque un envío falle.
  3. Agrega un except ValueError que reporte el dato inválido y siga enviando los demás. Al final, conexion.abierta debe ser False.

Pista: El try/except va DENTRO del for (para seguir con el siguiente dato); el try/finally va AFUERA (para cerrar una sola vez).

Código de partida

class Conexion:
    def __init__(self, servidor):
        self.servidor = servidor
        self.abierta = True
        print('Conectado a', servidor)

    def enviar(self, dato):
        if dato < 0:
            raise ValueError(f'dato negativo: {dato}')
        print('Enviado:', dato)

    def cerrar(self):
        self.abierta = False
        print('Conexión cerrada')

conexion = Conexion('servidor-fcfm')
for dato in [10, 25, -3, 40]:
    conexion.enviar(dato)
conexion.cerrar()
print('¿Abierta?', conexion.abierta)

Errores comunes en proyectos reales

Errores comunes en proyectos reales y cómo evitarlos

Ejemplos de la clase (ábrelos en PythonTutor)

  • Un except: que esconde un typo (así no: except: atrapa todo)
  • Un except: que esconde un typo (así sí: except específico)
  • Registrar y continuar: el patrón profesional

Reto integrador: code review de un script real 20 min

  1. Corre el código de partida: falla con KeyError: 'goma' aunque 'goma,3' es un dato válido. Encuentra la causa real, no el síntoma.
  2. Reescribe cargar_precios() con el checklist: try solo dentro del for, except específico y un mensaje útil por línea inválida.
  3. Guarda los errores en una lista y reporta al final cuántos productos se cargaron y qué líneas se rechazaron y por qué.
  4. Regla extra: un precio negativo también es inválido (usa raise).

Pista: El KeyError es el síntoma. Pregúntate qué pasó con las líneas que venían después de 'cuaderno,treinta'.

Código de partida

def cargar_precios(lineas):
    precios = {}
    try:
        for linea in lineas:
            nombre, precio = linea.split(',')
            precios[nombre] = float(precio)
    except:
        pass
    return precios

datos = ['lapiz,5.5', 'cuaderno,treinta', 'goma,3',
         'regla', 'borrador,-2']
precios = cargar_precios(datos)
print('Productos cargados:', precios)
print('Precio de la goma:', precios['goma'])
